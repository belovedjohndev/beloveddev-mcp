# M9-C2A: mock-tested OpenAI Responses boundary

## Scope and sources

M9-B verifies scripted MCP workflows. M9-C1 verifies the offline agent harness. M9-C2A adds a mock-tested provider integration boundary, not real LLM results. M9-C2B requires separate source review and explicit owner approval. No network transport implementation, live command, API key lookup, SDK dependency, or billable request is included. The existing eval and eval:agent commands remain offline.

Contract sources reviewed on 2026-10-29: [Responses create reference](https://developers.openai.com/api/reference/resources/responses/methods/create), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs), especially supported schemas and refusals. The reference documents input/output/total tokens, cached/cache-write input details and reasoning output details. max_output_tokens includes reasoning as well as visible output. The reference's generated Markdown omits schema detail; the official HTML reference was also inspected. No pricing or model availability is asserted by mock fixtures.

## Components and trust boundaries

Keep components in packages/mcp/test: openai-provider.ts, provider-budget.ts, provider-evaluation-report.ts, and openai-provider.test.ts. Extend agent-evaluation.ts narrowly to accept provider_mock adapters and provider-reported usage while preserving offline schemas and report labeling. Add vitest.provider-evaluation.config.ts and eval:provider:test for a redacted test-control report. Update README and implementation plan. No production application, MCP contract, authentication, domain, database, or migration changes.

The adapter implements ModelAdapter and requires an injected mock HTTP transport. No default fetch exists. Network transports and live authorization are rejected before credential resolution or HTTP invocation. Normal environment variables, API keys and CI flags cannot enable networking. Injected transports and adapters are trusted test code, not a sandbox against malicious JavaScript.

The model receives only the existing synthetic prompt, discovered read-only tool descriptions/schemas, and conversation/results. It never receives expectedClaims, scenario oracles, trusted RequestContext, repositories, environment dictionaries, DB credentials, or provider credentials. Credentials are injected by a private callback only for the transport header, never sourced automatically from the environment. Mock tests use ephemeral non-key placeholders. No raw provider errors or responses are logged.

## Request and response profile

Only POST https://api.openai.com/v1/responses is representable. Require application/json, reject redirects, and bound request/body consumption. Set store=false, stream=false, background=false, truncation=disabled, service_tier=default and tools=[]. No provider-hosted MCP, built-in tools, native function calling, attachments, persisted conversation or second execution path.

Use text.format=json_schema with strict=true. The root is an object containing action; action is a nested union. Tool actions contain a name and argumentsJson string, avoiding unconstrained JSON object properties in the provider schema. Final actions reuse the existing claims schema. Decode argumentsJson to the existing strict harness action; the existing gateway alone authorizes and dispatches tool selections. Unknown/write names remain observable selections and fail at that gateway. Never silently repair JSON or retry actions. The format constrains structure; it does not establish truth or permission.

Require an explicitly configured dated model snapshot and an exact matching response.model. Accept only a completed response with one completed assistant message containing one output_text, no annotations/logprobs, no error/incomplete details, and valid usage. Known optional response metadata is validated explicitly; unknown fields and other output item types (including reasoning/function/refusal) fail closed. This intentionally narrow text-only profile needs model-specific live compatibility review in C2B; it does not support all Responses models or every optional API feature. Reject malformed/truncated JSON, refusals, incomplete/interrupted states, mismatched models, missing output and inconsistent token totals.

Bounds: reuse C1 limits; additionally cap HTTP request at 128 KiB and response at 64 KiB, provider timeout at five seconds, action at 8 KiB. Propagate AbortSignal through HTTP headers/body work, bound each operation and cleanup, cancel readers on failure and attempt transport closure. No retries, including 429/5xx. Classify authentication, rate limit, service, transport, schema, timeout and cleanup failures with fixed safe codes. A completed response's usage is retained even when its action fails.

## Usage and future authorization

Simulated offline usage remains kind=simulated. Provider fields use kind=provider_reported; provider_mock execution and mock report provenance prevent presenting them as live measurements. complete=false means UNKNOWN or incomplete aggregate usage, never proof of zero billing. Keep known counters; stop further calls after missing/late/invalid usage or transport failure. Never recover or refund an uncertain reservation. Provider usage is accounting, not an evaluation oracle.

Define a separate strict live-run authorization data contract: invocation UUID, synthetic-data acknowledgement, owner approval, exact dated model, official pricing URL and verification timestamp, maximum provider calls, input-token estimate per call, maximum output tokens, aggregate token ceiling, and maximum planned micro-USD cost. This data cannot authorize networking in C2A. Pricing is supplied and reviewed externally; mock values are fictional, not current pricing. C2B must verify model availability, tokenizer/input-envelope allowance, pricing (including cache-write rates), approval provenance and freshness before use.

A ledger reserves the configured input upper estimate and output cap before every potential request, using integer ceiling arithmetic and the maximum supplied input/cache-write rate; cached input receives no discount. Validate planned worst-case calls against token and cost ceilings. Preflight uses an explicitly injected mock input-token estimator over the serialized request plus an explicit overhead allowance. Independently cap serialized request bytes. Reserve the full configured input allowance, not just the estimate, against remaining harness tokens. Mock estimation does not verify actual tokenization; C2B must supply and review a model-compatible tokenizer and provider-framing allowance before any live execution. This is not a provider billing guarantee. Reject underestimated/oversized requests before HTTP. Retain reservations rather than recycling capacity. Record validated actual input/output counts once and stop on overruns. Timeout/HTTP failure/missing usage consumes the reservation and marks usage unknown. Local limits and cancellation cannot guarantee final external charges; account-level billing controls are separate.

## Reporting and evaluation integrity

Preserve all six C1 scenarios and independent assertions. Existing selected/rejected/dispatched/completed distinctions remain unchanged; blocked writes fail, and model failures never pass. Existing version-1 offline aggregate reports accept simulated usage only. A dedicated version-1 mock_openai_provider_contract_validation report records passed/failed test counts and mock provenance, excluding prompts, actions, response bodies, credentials, IDs and URLs. Publication/collection/test failures exit nonzero. Ordinary Vitest developer diagnostics are not a universal redaction boundary.
