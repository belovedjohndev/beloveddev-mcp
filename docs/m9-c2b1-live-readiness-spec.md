# M9-C2B1: secure live-provider readiness (offline verification)

## Scope and existing limitations

M9-C2A is mock provider contract validation. M9-C2B1 implements the network/approval/token-estimation boundary and tests it offline. M9-C2B2 is future explicitly authorized real-model execution. No live OpenAI API requests, real credentials, owner signing keys, live launcher, environment activation flag, commits or pushes are permitted in B1.

Inspect C1/C2A specifications, provider, budget, agent runner, gateway, fixtures and tests first. Existing strengths: strict action/response profiles, seven read-only SDK tools, independent oracles, bounded calls/time/bytes, retained reservations and safe reports. Limitations: only mock transport/estimator, unverified approval booleans, no signed invocation capability, and no real response/schema/tokenizer measurements. The existing price schema accidentally retains a $1/M maximum on two fields; fix only that proven compatibility defect. The current API minimum max_output_tokens is 16; preserve mock tests but enforce that minimum before any network request.

## Files and dependency direction

New test-only files under packages/mcp/test: provider-live-approval.ts; provider-input-estimator.ts; provider-wire-contract.ts; openai-network-transport.ts; provider-live-readiness.test.ts. Modify openai-provider.ts, provider-budget.ts and agent-evaluation.ts narrowly; extend the existing provider reporter/configuration; update README and implementation plan. Add one exact development dependency, js-tiktoken@1.0.21, with its lockfile, for actual o200k_base encoding. No production exports, domain rules, authentication, MCP schemas, migration files or M8-G changes.

## Trusted approval and execution

An owner-signed Ed25519 document binds an externally supplied invocation UUID, synthetic-only acknowledgement, exact model, compatibility profile, all call/input/output/aggregate/cost limits, pricing verification time, issued/expiry times, owner public-key fingerprint and review reference. Verify against a separately supplied trusted public KeyObject, never a public key from the approval itself, scenario, model, environment or API key. Reject extra fields, bad/noncanonical signatures, wrong invocation/key/model, stale/future pricing, expired/future approval, lifetime over 15 minutes and replay within the process. Owner trust-key configuration is a future reviewed launcher responsibility, not an identity inferred from document contents.

Successful verification creates an opaque, nonserializable capability and its invocation-owned ProviderBudget. Check freshness and monotonic lifetime again before adapter construction, each request, and approved scenario execution. Ordinary runAgentScenario, eval, eval:agent and CI cannot accept live mode, even if keys or flags exist. A separate approved runner entry reuses the same loop/oracles; it requires the opaque capability and invocation ID as trusted arguments. Any CI marker rejects outbound live execution. Tests may stub CI only while native HTTPS and socket access are intercepted; no real owner approval is created.

Every request requires a fresh, one-use permit bound to the exact serialized body and actual budget reservation. The transport consumes it before native HTTPS creation. A copied/forged permit, a different budget, modified body or reuse cannot dispatch. An approval flag in scenario/model JSON cannot create either capability. Closing/revoking a capability prevents further sends. Replay protection is process-local; B2 must use new invocation IDs and protect approval files, keys, launcher code and OS account. This is trusted-code authorization, not a sandbox against malicious JavaScript or a compromised operator.

## Network and credentials

Only POST https://api.openai.com/v1/responses is accepted. Node HTTPS uses a private agent, explicit bundled CAs, certificate/hostname verification, fixed SNI/host/port/path, TLS 1.3 minimum, no global dispatcher, proxy configuration, redirects, URL overrides or retries. Explicit empty proxy settings isolate environment proxies; explicit certificate verification and CA configuration avoid environment TLS weakening. No alternate connector or custom CA is a runtime option. Native HTTPS tests replace the driver rather than adding a bypass to production code.

Validate the existing strict request profile, exact headers, body/model/output cap and permit before sockets. Credential callback stays outside model input and is invoked only after live approval/preflight. The callback supplies a private header; no environment key discovery. Bound headers to 8 KiB, request to 128 KiB, response to 64 KiB and wall time to five seconds. Reject redirects, unexpected encoding/content type/status, truncated/oversized bodies and incomplete connections. Propagate abort through socket/body work. Destroy owned requests/responses/agent on errors/close. Return only fixed error codes; never log headers, payloads, raw provider errors, prompts, owner documents or SQL URLs. Existing adapter retains HTTP 401/403/429/5xx classification and unknown usage on failure. Cleanup is bounded and idempotent; model and gateway cleanup remain independent.

## Token, usage and monetary safeguards

The live estimator is created by the supported-model factory using bundled js-tiktoken o200k_base ranks; mock counters or caller-created lookalikes cannot authorize live requests. Encode the entire serialized request, including instructions, descriptors, history and output schema, with literal special-token handling and 25 percent estimation margin. Require a separately approved framing allowance of at least 1024 tokens. Preflight against both remaining harness tokens and the signed per-call allowance. This is conservative estimation, not verified provider framing or a billing guarantee.

Reserve the full approved input allowance and requested output cap before credential/HTTP work. Retain every reservation, including failures; do not refund capacity. Validate and retain actual provider usage once, including counters on failed results/overruns. Missing/late usage is UNKNOWN, not zero; stop the invocation after uncertainty or overruns. Price input at a conservative non-discounted ceiling, with integer micro-USD rounding. Signed pricing must be verified within 24 hours, use the current official pricing source and be no lower than the reviewed profile rates. No account-level budget or final-invoice guarantee is implied. Provider-side generation may continue after local cancellation.

Keep existing C1 per-scenario limits (4096 total tokens, 512 output tokens, six turns, four tool calls). Measure the actual tool-catalog estimate offline. If these limits cannot fit the full catalog, fail before credentials/network and record the exact evidence as a B2 owner decision; do not silently raise limits, truncate context, weaken schemas or remove tools.

## Confirmed catalog preflight blocker

The offline representative request uses all seven discovered tool descriptions and strict input/output schemas plus the synthetic missing-project prompt. The pinned estimator measured 11733 input tokens (including its 25 percent margin); adding 1024 framing and 256 output tokens gives 13013, above the preserved 4096-token C1 scenario ceiling. Preflight rejects before credential resolution or HTTP. This is a local estimate, not measured provider usage. Full live scenarios are not ready under existing limits. B2 requires an explicit reviewed token-budget or prompt-contract decision; this slice changes neither. The version-2 readiness report records this blocker separately from passing safety controls.

## Compatibility profile and sources (reviewed 2026-10-29)

[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) documents snapshot gpt-4.1-mini-2025-04-14, Responses and Structured Outputs, with no reasoning step. [Deprecations](https://developers.openai.com/api/docs/deprecations) schedules shutdown January 14, 2027: refuse approvals at/after that date and never substitute another model. Documentation availability does not establish account access; no API availability probe is performed.

[Pricing](https://developers.openai.com/api/docs/pricing) currently lists standard text input $0.40/M, output $1.60/M and cached input $0.10/M. Reserve undiscounted input; cache-write ceiling must be at least input cost. These recorded rates are a review floor, not automatically refreshed quotes or an authorization to spend. B2 owner must recheck pricing, model availability, deprecation and service tier.

[Responses reference](https://developers.openai.com/api/reference/resources/responses/methods/create), inspected as official HTML because generated Markdown omits fields, documents max_output_tokens minimum 16, reasoning-inclusive output cap and input/output/total usage with cached/cache-write/reasoning details. Preserve completed-message-only strict response validation; fail on refusals, incomplete states, unknown fields or reasoning/function items. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) requires an object root, required fields and closed objects. [OpenAI tokenizer mappings](https://github.com/openai/tiktoken/blob/main/tiktoken/model.py) map GPT-4.1 to o200k_base; [js-tiktoken](https://github.com/dqbd/tiktoken/tree/main/js) is the bundled pure-JS port. [Node 24 HTTP](https://nodejs.org/docs/latest-v24.x/api/http.html) documents per-agent proxy handling. Actual TLS handshake, response compatibility, framing, latency, availability and billing remain unverified offline.

Reuse the existing SDK gateway and independent C1 expectations; a gateway-blocked write remains a failed model selection. Reports distinguish offline contract/readiness controls from live evaluation and never label mock fields as real LLM performance. Preserve C2A report compatibility and nonzero failure handling.

Run format:check, verify, db:check, verify:all, eval, eval:agent, eval:provider:test and diff --check, plus focused controls. Preserve migration hashes, existing Docker resources and other worktrees. Use an isolated LF-policy checkout if unchanged Windows CRLF baseline files interfere. B2 requires separate source review, trusted owner-key/approval provisioning, synthetic fixture composition, exact model and spending approval, account billing safeguards and a reporting/retention policy. No real provider requests in B1; no commit/push. Stop for source review.
